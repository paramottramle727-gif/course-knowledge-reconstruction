# 文件存放与信息所有权

## 两个互斥的目录

在课程的 `course-context.md` 记录解析后的绝对路径。新课程的 `agent_workspace_root` 位于 Obsidian Vault 外，通常为课程根下的 `角色/course-knowledge-reconstruction/`；若课程根在 Vault 内，选择库外的课程工作目录。`obsidian_output_root` 是 `obsidian_vault_root` 内专用于知识点的目录。优先从已指定路径及实际 Vault 配置（通常为 `.obsidian/`）识别库根。核对真实路径，包括链接或目录联接的目标；工作区与 Vault 互不包含。不能可靠定位时，只澄清缺失的路径。既有项目按末节兼容处理。

首次盘点及重启扫描限于允许的原始材料。即使允许范围是整个课程根，也先排除代理工作区、正式输出目录、已知旧稿和聊天预览/导出目录，再递归读取。原始课件确实存于 Vault 其他位置时按授权只读。审修指定旧章或读取获准样稿时，按该任务用途单独读取。

## Obsidian 中允许存在的内容

本 Skill 向展示目录只发布已验收的知识点正文和它实际引用的附件。用户在展示端的精修属于其学习成果。复习提纲、题型材料、作业、术语表、错题及其他课程阶段由原流程管理。

## 代理工作区中的内容

| 位置（相对工作区） | 用途 |
|---|---|
| `course-capability.md`、`course-context.md`、`execution-baseline.md` | O 来源策略、A 材料和架构及模块进度、B 完整方法。三个固定路径是新窗口和重启时的活动记录。 |
| `drafts/<轮次>/` | 首次 B 带编写说明的完整审阅稿；后续 B 的章节编写说明。同轮更新原文件，独立重启使用新轮次。O/A 的候选直接写入对应状态文件。 |
| `work/`、`audits/` | 当前候选正文、抽取和临时资源，以及实际审阅结论。覆盖核对等短期材料按需保存。 |
| `published/<模块ID>/<发布版本>/` | 经审阅的学习正文和资源，保留可验证的附件布局。模块记录指向最近一次**已完成发布**的版本。B 指针可长期固定在某一已批准版本。 |
| `backups/` | 覆盖或迁移前的恢复副本，按任务标明原路径。 |

按需建目录。阶段聊天链接直指工作区的状态文件或本轮审阅文件，章节交付链接指向展示正文。历史窗口的 `outputs/` 和预览副本仅供回看。原始材料按原路径和版本登记。

## 重启与状态更新

进入 O/A/B 时，从固定工作区读取对应活动版本、待确认区、确认依据和生效范围。讨论只更新本轮候选；确认后在原状态文件合并，保留简要历史与生效任务，无变化只记核对结果。独立重启只处理本阶段获授权的变化。状态更新前重读磁盘上的当前文件，只修改本次拥有的字段，避免旧窗口以整份旧文件回写。

- O 登记新材料时只更新 A 文件的材料清单。A 改地图时保留稳定模块 ID、旧新对应、既有发布记录和批次恢复点。改名、移动或拆分已展示的笔记属于独立授权的文件操作。
- B 更新编写方法时保留原样稿的校准版本、内部正文与资源、指纹和审阅稿路径。采用新样稿须明确确认；另存获批版本并记录历史。展示稿修改或新版 B 生效不会自行推进样稿指针。
- 章节开始时固定适用 O/A/B。重启确认记录的生效范围包括当前未完成任务时，按新依据复核受影响部分并更新恢复点。旧章沿用原生成记录，追溯修订走 04。

## 写入授权与版本保护

已授权改稿或迁移时说明源、目标和恢复路径，批量可统一说明。以内部上次发布内容和已记录的 SHA-256（正文及按相对路径列出的本地附件）核对当前展示文件。存在人工修改时，将展示端最新内容作为修订基础，与获准修改合并；写入前备份将被替换的正文和资源并再次检查目标。兼容的修改直接保留，冲突处无法同时满足时才请用户裁决。首次发布目标已存在或缺少历史指纹时，按已有文件核实身份与覆盖授权。需从头重做且旧稿被明确排除时使用无冲突的路径，不能为比对而读取排除稿。

同一资源被多章引用时，变更优先使用新资源名并只更新本章引用。撤下引用不授予删除附件的权限。展示端变化也不授权同步改写历史校准样稿。

## 候选稿晋升与正式发布

1. 必要的内容、阅读、图文与技术检查完成且无关键待决项后，将学习正文和实际依赖的附件定版到本次内部发布路径。首次 B 获批时从审阅稿提取学习正文，清理批注后复核知识内容、目录和链接；B 记录指向这份可复取的确切版本。内嵌资源随正文保存。
2. 写展示端前，在现有模块恢复点登记“已验收、待发布”、本次定版路径、目标、所用 O/A/B 和恢复位置。记录本次各目标文件的原状（包括尚不存在）及拟发布指纹，可引用工作区的一份资源清单。保留上次成功发布记录，直至本次完成。
3. 按版本保护规则先就位新附件，再写正文。写入后记“已写入、待复核”。在正式路径复核正文与附件指纹、链接、可用阅读环境中的显示；环境限制如实报告。通过后更新模块发布记录、指纹和完成状态。普通章节按需要留恢复版本，保留仍被校准、恢复或历史审阅引用的版本。
4. 若中断，逐项对照磁盘与恢复点：等于拟发布内容的跳过写入；等于原状的补完；两者都不符的按人工变更保护。即使中断发生在写入和更新状态之间，也以磁盘核验决定下一步。未完成最终复核时留在当前单元。

## 既有混放文件

旧课程先按已有路径只读核对活动状态、用户修改和样稿身份。旧 `representative_file` 仍可作为历史定位线索；依据原校准记录、正文及必要附件核实获批版本。身份不清时查找已批准的审阅稿、发布备份和既有指纹，不能以当前展示文件倒推批准。受影响的样稿对照暂缓，其他独立工作可继续。

库内旧工作区或旧目录混放时说明源、拟定库外目标、引用和需保护的文件。迁移须另有授权：先备份，再复制并校验状态、样稿及资源，核对新窗口读取和历史链接，最后切换路径。未迁移期间兼容旧记录，不擅自搬动或删除旧文件；新建内部产物使用已确定的库外工作区，缺少可用目标时先解决该路径。
