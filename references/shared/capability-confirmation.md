# 确认点 O：来源使用策略

## 职责边界

O 共同确认哪些来源用于什么、利用到什么程度、在该用途内依据谁。记录学习目的、已知读者基础、教师明确说明和来源使用限制；不在初始化时替各章完成详细能力判断、知识点取舍或笔记底线设计。

- A 根据来源约定设计材料—模块映射、顺序与文档分工。
- B 及后续逐模块生成深入分析相应材料，识别具体任务，决定详略、推导、例子与图形角色。
- O 不要求独立的全课“知识广度表、能力清单、笔记底线表”。明确指定的文件/章节/题目范围直接写在来源策略中，不再复制成内容清单。
- “某章不考”等教师信息保留依据与原意，不自动等于不进入学习笔记。AI 的初步课程认识不得随 O 整体获批升级为不可修正的逐章要求。

## 初始 O

1. 明确梳理用途，按[目录与来源边界](storage-policy.md#两个互斥的目录)扫描允许材料，盘点身份、版本、可读性和归属，清单存入 `course-context.md`。读者基础沿用[首次学习的默认起点](content-decision-rules.md#目标读者与首次学习)。已有课程先修说明或用户补充时记录相应调整，无须另行盘点或确认读者背景。模块架构留到 A。
2. 按 [evidence-policy.md](evidence-policy.md) 提出文件组的用途、范围、程度及用途内优先关系。来源可以多用，不按文件类别固定排名。
3. 邀请用户补充材料未记录的教师口头说明、课堂强调、作业与考试关系等课程情境。不要重复索要已有文件，也不要求用户代替代理逐项审批抽象能力。
4. 用 [O 模板](../../assets/course-capability.template.md) 保存初步策略及讨论后的修订。依据与理由就近标注，集中列出实际影响来源决策的未知或冲突；没有则省略。草案可在情境补充前形成，但不能提前作为完整待批准方案。
5. 按下述文件与聊天框架及 [双路交互规则](checkpoint-interaction.md) 提交本轮结果，区分补充情境、讨论取舍和整体确认。
6. 用户明确确认整体方案后，记录 O-v1、确认时间和生效起点，首次流程中，已有 A 执行授权则继续，否则询问是否进入 A。文件与简报只需一次确认；修改意见同步回文件。

未知事项可保留，但应明确影响。若缺口使来源策略或架构无法可靠确定，停在相应决策，不用同类课程常识补齐事实。

## O 的文件与聊天框架

正式文件 `course-capability.md` 包含：

- 当前活动/候选状态、版本及修订时间；学习目的与已知读者基础。
- 来源策略：文件或来源组的用途、范围与程度、用途内优先关系；各项的简短理由及材料或用户情境依据，区分推断。来源可承担多个用途，不能仅列“主用/补充”标签。
- 会影响使用的教师说明、限制及关键未知/冲突；说明其影响和需要补充或选择的内容。不另外构建全课细节能力清单。
- 增量更新时保留原策略、候选变化、变化依据及拟生效范围；确认后记录历史，不覆盖仍有效的策略。

### O 聊天模板

首次提交、重大修订和整体确认使用以下栏目；普通讨论按双路交互规则简化。填写实际内容，不照抄提示。

```text
本轮类型：首次建立 / 后续更新
当前状态：讨论中 / 待确认 / 已确认
方案文件：[来源策略链接]
策略版本：当前有效版本；候选版本（如有）

1. 来源使用方案
按用途说明采用哪些来源、利用程度和用途内优先关系。

2. 关键依据与理由
解释主要安排，区分材料/用户已知信息与代理推断。

3. 需要你参与的事项
待补充的课程情境或待决定的取舍，以及它们影响什么。

4. 下一步
补充后修订或提交整体确认；首次按授权衔接 A，后续更新默认结束。
```

来源允许多用；重大排除或用途降级须在简介中可见。不以“某教材是否只能补充”等预设结论代替中性事实询问。关键事实未解决时不捆绑整体通过请求。材料清单仅在需要核对时另链，常规读取与格式检查留在内部。

## 后续增量 O

用户明确要求重新讨论来源策略、使用程度或课程情境时进入；仅检测到新材料不触发。

1. 读取原有效 O、相关 A/B 约束及保护边界，沿用首次扫描边界核对指定的新增/更新文件和情境。材料清单变化限于原 A 文件相应部分。以原记录及可见版本比较变化；旧原件不可得时注明，不能推测其原内容。
2. 比较“新增依据 → 原策略 → 候选调整 → 对后续任务及 A/B 的影响”。变化可标新增、强化、细化、修正、冲突或不变；只处理实际相关部分，不从头裁决全部来源。
3. 在原 O 文件待确认区保存草案，按 O 聊天模板标注“后续更新”；方案栏目重点说明保留与改变，依据栏目解释变化原因，下一步说明拟生效范围及是否存在需另行决定的联动。
4. 人机讨论后确认新版，合并活动策略、记录确认依据/时间、生效起点和简要历史。用户已明确给出完整新策略及范围时可作为对应确认。策略不变时记录核对结果，不为走流程强行改版。
5. 本次重启默认到此结束，不自动启动 A 或 B，也不反复询问是否必须开启下一阶段；仅提示真实冲突及影响。用户明确授权联动更新时，O 确认后才用新策略进入 A。

待确认期间旧版本继续有效，候选不用于生成；尚未解决的实质冲突应暂停受影响任务。确认后从下一项分析任务或用户指定的未完成任务生效，不把未讨论的推断混入新策略。

## 版本与向前生效

`course-capability.md` 是来源策略唯一活动记录，保留当前内容、待确认差异与简要变更历史。确认状态和证据强度分开，类型及标记统一按证据规则；获批不把推断变成教师原话。

更新不自动审查、重写、删除既有章节，不改变其生成时的 O 记录；也不使 A、B 或参考样稿失效，不重新划分模块。与架构或编写共识出现实质冲突时，指出具体影响，再由用户决定是否调整相应阶段。追溯审修需要另行明确范围并进入 `audit-and-update`。

## 旧版项目兼容

- 已有 O/A/B 不因升级重开；旧 O 的来源策略和有依据的明确用户要求继续有效。旧的广度、能力或笔记要求表不复制到新模板；其中 AI 推断须回到当前材料检验，不作为逐章不可更改的取舍命令。无法区分明确要求与推断且影响执行时，仅核查该项。
- 旧策略在 `course-context.md` 或 `.knowledge-system/` 时兼容读取；下次主动 O 更新再统一归属，未经授权不迁移文件。
- 已有 A/B 但完全没有可见的 O 确认记录时，补建初始 O，仅向前应用，随后恢复原进度。
- 文件名继续沿用 `course-capability.md` 以保持兼容，不另建同义来源策略文件。
