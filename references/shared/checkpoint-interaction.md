# O/A/B 双路交互

阶段文件承载可核对的完整方案与必要依据，聊天帮助用户理解当前方案、参与取舍并知道下一步。两者是同一方案的两种呈现，不增加审批点或另建聊天摘要文件。各阶段的具体内容框架见 O 确认规则、A setup 和 B calibrate。

## 本轮状态与交互

| 本轮状态 | 文件处理 | 聊天重点与下一步 |
|---|---|---|
| 讨论中 | 保存有依据的草案或候选差异，区分事实、推断与未决项；用户反馈改变方案时同步更新 | 当前方案及关键理由；需补充的事实或需权衡的选择，以及它们会改变什么。关键问题尚未解决时，不同时要求整体通过 |
| 等待确认 | 形成一致、可审阅的候选版本，标明仍保留的假设、限制及其影响 | 链接、方案要点、关键理由与限制；明确这次整体确认的对象及生效范围，不再夹带决定方案所必需但尚未回答的事实问题 |
| 已确认 | 记录确认依据、时间与生效范围；区分当前活动版本和历史记录 | 简述已确认内容、起效任务及下一步；已有执行授权时继续推进到下一必要确认点，不再次索要同一批准 |

这是交互状态，不是新增阶段或必须逐次停顿的三道门槛。已知信息充分时可直接提交确认；明确完整的用户指令可按对应 O/A/B 阶段规则构成确认。非关键未知可明确保留后提交，不能以消除所有不确定性为由无限追问。

## 两路内容对应

- **角色目录中的阶段文件**：完整保留本阶段决策及理由、依据定位、重要限制和未决事项，聊天链接指向该课程工作区的固定状态文件或本轮审阅稿。给候选标明可识别的版本/修订时间，避免把草案版本写成已生效版本。
- **聊天简介**：按对应阶段的框架呈现“状态与链接 → 方案及关键理由 → 需要用户参与的事项与下一步”。应能据此理解在决定什么；不要求用户先打开多个内部文件才能知道问题，也不复制完整文件。
- **后续讨论轮次**：使用下方简化格式，不反复铺陈未变内容。只解释规则或回答问题、没有方案变化时，无需重新写文件或整套汇报。
- **一致性**：重要限制、关键未决项和会改变用户判断的取舍不能只藏在文件里。提交前对照本轮文件，检查聊天所述方案、状态、变化和生效范围是否一致；用户修改同步回唯一候选，不产生相互冲突的多份审阅稿。

## 信息优先级与提问

先说明决策，再提供足够理由；事实核实、用户偏好和整体确认应明确区分。对未知事实中性提问，说明其影响，不能让用户以批准方案的方式证明代理推断。材料身份、版本差异或文件类别本身不能代替用途与重要程度的证据。

完整路径清单、读取页数、常规可读性与格式检查结果留在内部记录；聊天只链接主要审阅文件和必要定位。影响范围、可靠性、确认或文件安全的异常用独立短提示告知，写明已知事实、影响和未核实部分，不埋入常规日志。

## 模板使用与简化

首次提交、重大修订及整体确认，使用各阶段规定的状态栏和编号栏目名称、顺序，具体句式与篇幅按实际内容决定。无待决问题写“无”，无需提问；确实不适用的栏目可省略，不为填栏目制造分歧或验证结果。已确认后简报结论与下一步，不再次要求批准。

普通讨论轮次使用：

```text
当前阶段与本轮类型：O/A 首次建立或后续更新；B 首次校准或后续更新
当前状态：讨论中 / 待确认 / 已确认
当前文件：[链接与可识别版本]

1. 本次反馈与对应修改
说明用户反馈、实际调整和必要理由。

2. 剩余问题与下一步
只列仍需参与的事项和影响；无问题时说明接下来的动作。
```

模板用于最终阶段汇报，不要求每条进度消息套模板。提交整体确认前恢复对应阶段的完整简介，确保重要方案没有被差量汇报遗漏。
