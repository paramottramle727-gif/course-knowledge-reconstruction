# 嵌入已有课程学习流程

## 定位

本 Skill 是“知识点梳理阶段”的局部执行器，不是整门课程的学习规划器。引入已有课程学习窗口时，保留原有课程规划的连续性，只重新建立或执行知识点梳理阶段。

## 先做只读边界盘点

在 O 之前，读取用户允许访问的现有课程规划和阶段成果，识别：

- 当前课程学习阶段与进度；
- 已确认的课程目标、阶段划分和任务安排；
- 已存在的目录分工和文件命名约定；
- 用户已人工修改或明确保护的成果；
- 本次允许读取的课程原始材料、Vault 根及原有工作区，按[存放与兼容规则](storage-policy.md)核对扫描排除项、旧活动记录及样稿身份；
- 本 Skill 获得授权的两个写入位置。

把课程规划、学习进度、任务安排、作业流程和其他阶段成果标为“受保护的上游约束”。读取它们是为了避免冲突，不代表获得修改权限。

## 授权写入范围

本 Skill 只能写入：

1. `obsidian_output_root`：已转正、通过本轮 QA 的正式知识点文件及其必要附件；
2. `agent_workspace_root`：来源使用策略状态、课程上下文、执行基准、候选稿、覆盖核对和 QA 等内部文件。

不得移动、重命名、覆盖或重排现有课程规划、学习进度、其他阶段产物及其目录。不得借知识点重构之名生成复习提纲、题型材料、作业系统、错题系统或新的全课程学习方案。

## 既有知识点的处理

- 用户明确要求废弃并从头重做时：把既有知识点路径列入排除项，不读取、不引用、不修改。
- 用户允许作为证据或风格参考时：只按用户指定用途读取；人工修改稿优先于旧生成稿。
- 用户未说明时：先把既有知识点列为待确认来源，不默认继承，也不默认删除。

## O、A、B 与既有规划的关系

- O 确认本次梳理的来源用途、使用程度及重要性，记录明确课程情境；不预先决定逐知识点取舍，不改写已有课程目标或学习规划。
- A 设计材料—模块映射、划分与顺序、文件分工；首次 B 用第一模块，旧项目保留原参考样稿。不重新规划整门课程学习阶段。
- B 以真实阅读校准内容组织与表达呈现，可由用户主动更新；方法向前生效，不影响其他阶段标准，也不自动审修既有笔记。

既有课程规划是上游约束，O/A/B 是知识点梳理阶段内部的门槛。二者出现冲突时，明确列出“现有约束—拟议方案—冲突影响”，停止相关设计并等待用户裁决；不得静默修改上游规划，也不得假定 Skill 的判断自动优先。

升级通用 Skill 不自动修改本课程状态或重新要求 O/A/B。已有来源策略和基准按兼容规则继续有效；用户主动发起 O/A/B 更新或单独要求修订时，才处理相应课程变化；各阶段更新与旧章修订授权彼此区分。

## 退出报告

交付时简要说明：

- 本 Skill 接管的知识点梳理范围；
- 保持不变的课程规划和既有成果；
- 正式知识点目录与代理工作目录；
- 当前 O/A/B 状态；
- 发现但未擅自处理的上游冲突。
