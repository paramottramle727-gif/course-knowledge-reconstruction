# 主导适配器：编程与算法

## 适用条件

仅当语言规则、程序执行、数据结构、算法设计或复杂度判断构成模块主体时，作为唯一主导适配器。

## 宏观组织

围绕“问题/规则 → 状态与执行过程 → 输出或异常 → 方法选择与边界”组织。数据结构与算法同时出现时，以当前模块真正被考核或调用的对象为主线。

同一算法或操作内部的前置条件、状态变化、执行步骤、正确性依据和复杂度等实际属性，按 [内容属性与标识规则](../shared/content-decision-rules.md#板块内部的内容属性与标识) 组织；保持代码、状态追踪与对应解释相邻，不逐语句拆成标题。

## 内容取舍

- 代码示例必须验证一个明确规则、状态变化、边界或错误；
- 能用短伪代码说明的算法，不为展示语法扩展成长程序；
- 解释关键状态如何变化，避免只展示输入和输出；
- 明确数据结构操作的前置条件、不变量、复杂度口径和失败情形；
- 区分课程教学口径、语言规范和具体实现行为；差异会影响答案时采用双层说明；
- 不把入门课程扩展成语言或库函数手册；课外底层细节须通过外部知识准入。

## 验证

在安全且可执行的环境中验证关键示例输出、边界和异常。无法运行时明确标注为静态推断，不声称已经执行。

## 高风险检查

- 把语法规则、运行时行为和实现细节混为一谈；
- 忽略空输入、越界、重复元素、稳定性或可变状态；
- 只背复杂度结论，不说明输入规模和操作模型；
- 示例代码引入超出课程范围的大量辅助概念。
