# calibrate-course：继承、验证与迭代编写共识

## 入口与基础

首次 B 在 O、A 通过后运行，默认使用 A 的第一模块；尊重用户明确指定及旧项目样稿。后续 B 由用户主动发起，不因新材料、普通新知识类型或 Skill 升级自动启动。

B 以课程编写共识为起点，通过真实阅读验证并修订方法。共识分内容组织、表达与呈现两类，并区分整课、知识类型与单章范围。样稿是方法的实例，不代替共识正文；局部修复不自动变成长期规则。

## 首次 B：基础保存与前置阅读

1. 实际读取 [内容组织](../shared/content-decision-rules.md) 和 [表达与呈现](../shared/presentation-rules.md) 的完整正文。不能以文件名、链接、简短摘要或旧样稿代替。读取失败时补齐，不跳过后直接写正文。
2. 用 [课程共识模板](../../assets/execution-baseline.template.md)，在 `agent_workspace_root/execution-baseline.md` 保存 B-v0。保存完整的基础编写要求及必要适用条件，按两类组织；只剔除工具命令、文件管理和工作流操作，不把方法缩成口号。记录基础文件路径、Skill revision、保存日期及用户已明确的偏好来源。B-v0 是首次样稿的可用起点，尚未经课程校准，不代表 B 通过，不能据此批量生成。已有共识不覆盖重建。
3. 编写前依次读取有效 O（来源使用边界）、A（首模块材料与前后接口）、课程 B-v0 正文（本轮写法），再深读本模块允许的课件、训练及必要补充。按需要读取主导适配器、[证据规则](../shared/evidence-policy.md)、[存放规则](../shared/storage-policy.md) 和 [双路交互规则](../shared/checkpoint-interaction.md)。
4. 在既有基准的本轮阅读记录中简记实际读取的共识版本、基础来源、O/A 依据及相关材料定位；记录不能代替阅读。不另建阅读证明报告，也不增加保存 B-v0 后的批准门槛。

## 首次 B：分析、样稿与核查

1. 根据材料识别本章对象、任务、条件及读者障碍，区分明确要求与教学推断；不执行 O 预设的全课细节清单。
2. 按课程共识确定主线、内容取舍、同类框架、解释单元、推导、算例与图形角色。把关键方法落实到具体安排，不复制样稿布局；必要时用临时 [覆盖核对表](../../assets/coverage-checklist.template.md)。拟偏离当前方法时明确原因、候选调整和范围，不能静默替换共识。
3. 生成一份含完整学习正文及编写说明的 B 审阅稿，形式见下节。无需先批准一份独立编写方案。
4. 保存本轮样稿后，重新打开[单模块审阅提示](../shared/module-review.md)，按首次 B 的依据重读、审阅并修正复核。将未涉及的知识形态记为未验证，再提交用户校准。
5. 人机讨论后按问题归因修订样稿、说明与候选方法，复核受影响部分。用户确认本版样稿及可迁移方法后，合并为 B-v1，记录确认和生效点；首次 B 内受新方法影响的样稿必须同步修订，不能批准互相矛盾的方法与样稿。
6. 按[定版与发布](../shared/storage-policy.md#候选稿晋升与正式发布)保存获批学习正文及资源，登记内部样稿路径、校准版本、展示路径和本轮审阅稿，再发布并复核。后续按已有授权逐模块生成，不额外等待再次唤醒。

## 审阅内容与呈现

### 首次 B 文件

保存 `agent_workspace_root/drafts/<轮次>/<模块名>-B审阅稿.md`：状态与修订版本、采用的共识版本、完整学习正文、两类编写说明、拟迁移范围及未验证事项。除用户另有要求，不另产独立说明报告、纯净样稿和对照稿。

说明可集中在文首/末并链接正文，必要局部批注靠近内容、标明“编写说明”，不打断连续推导。学习所需条件、推理与操作必须留在正文，不能靠批注补齐。

### 两类编写说明

- **内容组织**：本章任务及证据；顺序、前置与同类框架；重要内容的纳入、详讲、简述、合并、省略或后置理由；推导、算例及图形角色与位置。
- **表达与呈现**：影响阅读的语言、标题命名和编号、解释单元标识、符号条件、粗体与图文安排。完整样稿承担语言体验，不另建评分表。

按实际方面用简短分类名，条目采用“具体决策 → 理由/依据 → 正文位置”，不长段堆叠或逐句辩护。解释关键共识如何落实，另列拟调整方法及其范围；普通章节取舍不冒充方法升级。省略的重要内容须能定位，未读材料不声称已覆盖。未变的通用原则不在说明中整篇重抄。

## 反馈与确认

先区分问题：

| 类型 | 处理 |
|---|---|
| 已有共识未执行 | 修复执行，首次 B 同步改样稿；不追加同义规则，不为此强升方法版本 |
| 共识不充分或不合适 | 比较原要求、问题依据、候选要求与适用范围，讨论确认后更新 |
| 单章内容或局部安排问题 | 保留在该章，不能直接推广为课程共识 |
| 来源、架构或读者依据有误 | 核查证据；实质涉及 O/A 时说明影响，由用户决定相关调整 |

无回复、局部认可、代理自检均不等于首次 B 整体通过。普通后续知识类型未验证只限制迁移范围，不阻止首次 B 转正。明确要求后续执行某条新方法，可作为该条确认，不连带批准其他代理建议。

## 用户主动发起后续 B

1. 依次读取有效 O、A、当前课程 B 完整正文及其内部校准样稿，再读取用户指定章节及相关原始材料。核对该章生成时的 O/A/B 版本和当前版本，避免用后来要求伪造当时缺陷。用户未指明具体章节时用可见反馈定位；确实无法定位则先澄清，不虚构对象。
2. 保存 `agent_workspace_root/drafts/<轮次>/<模块名>-B编写说明.md`，不重新生成或附带整章知识点正文。文件包含状态、章节路径/版本与标题定位、本轮共识依据、上述两类编写说明、问题归因、候选修改与适用范围。区分原记录可证明的依据和现在对正文的分析，不能事后编造原编写理由。复用同一轮说明，不为每次回复新建文件。
3. 按下节聊天模板简介。只读解释指定章节不授权改写该章；必要时可在说明内给短示例，不能借此交付整章新稿。未涉及的其他章节不批量审查。
4. 讨论后把候选方法写入基准待确认区，独立说明只引用该候选及其理由，不形成另一份活动规则库。确认后合并成下一版完整课程共识，替换冲突条目，记录变化与生效点。只有执行偏差或结论不变时不强行升级。
5. 新版默认从确认后的下一任务生效；用户指定未完成单元时明确记录并复核相关部分。旧章修改需另行明确授权并进入 [audit-and-update](04-audit-and-update.md)。不自动修改旧样稿、重启 O/A 或回溯全课。

## B 聊天模板

按 [双路交互规则](../shared/checkpoint-interaction.md) 在首次提交、重大修订和整体确认时使用以下栏目。填写真实内容，不照抄占位提示：

```text
本轮类型：首次校准 / 后续更新
当前状态：讨论中 / 待确认 / 已确认
审阅文件：[链接]
共识版本：本轮依据版本；候选版本（如有）

1. 本轮审阅对象
模块及本轮重点检验的问题；文件内阅读与解释入口。

2. 内容组织
关键编排、详略、推导、算例或图文决策及理由。

3. 表达与呈现
主要阅读安排及作用。

4. 共识的沿用与调整
沿用的方法、拟调整内容、问题归因、适用范围与未验证部分。

5. 待决事项与下一步
需要用户判断什么，确认对象及生效范围。
```

首次链接完整审阅稿；后续链接独立编写说明，必要时补课程共识链接。文件与聊天同版同义，只确认一次，不要求逐项填写审核表。普通讨论采用共用简化格式。

## 样稿、版本与迁移

- `execution-baseline.md` 是当前完整课程共识的唯一活动文件，保留基础来源、当前正文、候选修改和简要历史。首次 B-v0 可用于校准；首次确认前的 B-v1 仅为候选。后续待确认期间原活动正文不变。
- 课程共识包含完整有效编写方法，工具、发布与检查流程仍由 Skill 负责。通用 Skill 更新不静默覆盖课程已确认方法；读取共享规则执行检查时，方法冲突按当前课程版本处理，实质正确性或范围冲突需说明。
- 保存历史备份用于恢复，不把多份完整版本并列为执行依据。新版本合并同义项、替换旧要求，不维护额外的例外表。
- 样稿校准版本与方法版本分别记录。新方法优先于历史样稿；后续更新不反写样稿已验证范围。更换参考文件需明确确认；同一文件授权修订按 [基准治理](04-audit-and-update.md#反馈与基准治理) 处理。
- 旧项目差异表兼容读取，不因升级重开 B 或覆盖课程文件。下次获授权更新 B 时，将可追溯的基础与已确认差异合并为完整共识，保留原批准与范围；基础版本不可追溯时明确缺口，不用最新版伪造旧共识，影响方法判断的缺失部分先讨论。已有项目不补造 B-v0 历史。
- 初始 B 未通过不得批量生成。增量 B 不自动使旧版失效；只有明确暂停请求、关键缺口或实质冲突时停止受影响任务。
