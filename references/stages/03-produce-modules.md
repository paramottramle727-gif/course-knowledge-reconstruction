# produce-modules：正式模块生成

## 进入条件

确认点 O、A、B 均已通过。每个新单元按 O → A → B → 本章材料的顺序实际读取，仅使用已确认且已生效、适用于本单元的版本，不以最新保存的候选草案代替：

1. `course-capability.md` 中最新已确认且已生效的 O 版本，包括来源用途、范围、程度及明确课程情境；
2. `course-context.md` 中有效 A 版本、材料映射、模块边界、顺序和前后接口；
3. `execution-baseline.md` 中最新已确认且已生效的 B 方法版本、完整的内容组织/表达呈现共识及适用范围（不能只读版本和指针）、未验证事项；
4. 基准文件登记的内部校准样稿及其必要资源（旧项目按存放规则兼容）；样稿历史写法与当前方法不同处，以当前有效课程共识为准；
5. 当前目标模块的原始材料；
6. [content-decision-rules.md](../shared/content-decision-rules.md)；
7. 当前模块唯一主导适配器；
8. [presentation-rules.md](../shared/presentation-rules.md) 和 [storage-policy.md](../shared/storage-policy.md)。涉及来源用途、教材题覆盖或材料冲突时，另读 [evidence-policy.md](../shared/evidence-policy.md)。

代表模块不可读或识别信息不符时，按 [04-audit-and-update.md](04-audit-and-update.md#反馈与基准治理) 核对版本与授权后再继续，不把指纹变化直接等同于 B 失效。

## 单模块流程

1. 固定本单元使用的有效 O/A/B 版本，深读 A 对应的课件与训练，按内容规则识别本章对象、任务动作、条件/标准及必要前置。核对前后模块接口，不用 O 的旧能力摘要、样稿或上章经验代替当前材料证据；不把题目顺序直接变成主线。
2. 按内容规则建立临时四列覆盖核对，先决定去向，再判断主线、逻辑归属、同类知识框架及各单元图形角色。按解释功能划分组段后选择标题/短标签，不因样稿有某栏目就新增内容。
3. 按当前完整课程共识及真实参考样稿生成候选稿，不以通用新版静默覆盖课程方法；交叉知识只调用对象级局部规则。进入审阅前将当前稿保存到 `agent_workspace_root/work/`，实际读取该文件审阅；审阅对象须与拟发布正文及附件一致，不能只检查提纲、生成计划或记忆中的正文。
4. 在适用条件内落实已确认编写共识，不复制样稿目录或详略比例。样本未覆盖的新知识形态可采用适当局部结构，按本单元实际任务验证；新增写法标记为候选规则，不擅自改变全课基准。普通差异不重开 B，实质冲突按批量停止条件处理。
5. 初稿保存后，重新打开并完整读取[单模块审阅提示](../shared/module-review.md)，按其顺序重读有效 O/A/B、内部校准样稿、本章映射的原材料及当前稿，完成审阅、修正和复核。
6. 达到审阅通过条件后，按[定版与发布](../shared/storage-policy.md#候选稿晋升与正式发布)保存内部版本并发布，复核最终位置。完成前保持候选状态。

## 批量范围

本节同时适用于 `produce-modules` 和已授权的批量 `audit-and-update`：

1. **批前全局核对**：明确授权章节、顺序、全局依赖、符号约定和内容归属。可预读相邻章节以确定接口，不提前撰写下一章正文、修订稿或集中生成后续配图。
2. **单个活动单元**：按一章或 A 已确认的独立模块执行上述流程；修订则执行审查阶段的单元审修。不得拆成细标题绕过闭环。
3. **落地后重新进入流程**：本单元审核通过、发布、最终位置复核并记录完成后，下一生成单元从本文件的进入条件和单模块第 1 步重新开始；候选稿形成后重新进入单模块审阅。上一单元结论仅用于接口核对，不能作为本单元通过依据。修订单元按 04 的单元审修重新开始；无需改动时可记录“已核查、保留原稿”后继续，不为制造变更而重写。
4. **未通过留在本单元**：问题须先修正复核，不得先积累后章草稿再批末补审。发现实质冲突、重大来源缺口或需要用户决定的问题时，暂停并说明。
5. **内部验收不新增人工门槛**：默认在本单元内部验收通过后自动继续本批任务，不要求用户逐章回复“通过”；用户明确要求逐章人工确认时才等待。O/A/B 原有门槛不变。
6. **恢复与跨章检查**：在现有 `course-context.md` 的模块状态和简短批次记录中记当前单元/步骤、使用的 O/A/B 版本、已完成项及待决问题，必要时链接内部单元记录而不复制。上下文中断后核对版本与当前稿，从未完成步骤恢复，不能把候选稿当已交付。中途更新从声明的生效任务应用；批末仅补查跨章重复、符号、前置和链接，不代替单章验收。

前一单元的临时偏差不得成为后续全课规则。批量工作可跨多次执行连续完成，但每次结束须如实报告已落地、当前未完成与尚未启动的范围，不以批量提速为由省略单元闭环。

## 交付

逐单元简报交付路径、适用 O/A/B 版本、B 与样稿对照结果、实际修复的主要问题，以及内容/阅读、图文和技术检查的实际范围、结果与未验证项。聊天只摘关键结论，不复制内部逐项记录；无相应对象时说明不适用。

存在的外部补充和候选规则简短说明；批次区分已完成、当前待修及未启动。
